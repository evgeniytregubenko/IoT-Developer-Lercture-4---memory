# Переповнення типів та розміщення змінних у пам'яті

## 1. Переповнення на прикладі uint8_t

Розглянемо наступний код:

```cpp
uint8_t a = 200;
uint8_t b = 100;
uint8_t sum = a + b;
```

Тип `uint8_t` — це беззнакове 8-бітне ціле число

Його діапазон:

```text
0 ... 255
```

Математично:

```text
200 + 100 = 300
```

Але `uint8_t` може зберігати максимум 255, тому відбувається переповнення.

Для беззнакового 8-бітного числа результат визначається за модулем 256:

```text
300 mod 256 = 44
```

Отже:

```text
sum = 44
```

У програмі тип `uint8_t` використовується, наприклад, для зберігання статусу сенсора:

```cpp
uint8_t sensorStatus = 0b00000000;
```

Тут 8 бітів використовуються як окремі флаги стану:

```text
Bit 0 = temperature OK
Bit 1 = humidity OK
```

Наприклад:

```text
00000000 — температура ERROR, вологість ERROR
00000001 — температура OK,    вологість ERROR
00000010 — температура ERROR, вологість OK
00000011 — температура OK,    вологість OK
```

## 2. Розміщення змінних програми у пам'яті

У програмі використовуються різні області пам'яті: stack, heap, .bss та flash.

### Stack — стек

Стек використовується, зокрема, для локальних змінних функцій.

У функції читання DHT22:

```cpp
bool readDHTData() {
  float humidity = dht.readHumidity();
  float temperature = dht.readTemperature();

  uint8_t sensorStatus =
      validateSensorData(temperature, humidity);

  ...
}
```

`humidity`, `temperature` та `sensorStatus` — локальні змінні функції `readDHTData()`.

Вони існують під час виконання функції. Після виходу з функції місце у стеку, зайняте цими локальними даними, може бути використане наступними викликами функцій.

Ще один приклад:

```cpp
void handleButton() {
  bool reading = digitalRead(BUTTON_PIN);
  ...
}
```

`reading` також є локальною змінною і належить до автоматичних даних функції, які зазвичай розміщуються у стеку.

---

### Heap — купа

Heap використовується для динамічного виділення пам'яті під час роботи програми.

У нашому коді немає явного використання:

```cpp
new
malloc()
```

тому програма сама безпосередньо не виділяє динамічну пам'ять цими засобами.

Для контролю вільної heap-пам'яті ESP32 використовується:

```cpp
ESP.getFreeHeap();
```

У програмі перевірка виконується кожні 60 секунд:

```cpp
Serial.print("Free Heap: ");
Serial.print(ESP.getFreeHeap());
Serial.println(" bytes");
```

Під час тестування протягом 5 хвилин отримано:

```text
60 s  -> 351012 bytes
120 s -> 351012 bytes
180 s -> 351012 bytes
240 s -> 351012 bytes
300 s -> 351012 bytes
```

Обсяг вільної heap-пам'яті не зменшується:

```text
Δ Heap = 0 bytes
```

Отже, під час тестування ознак витоку пам'яті (memory leak) не виявлено.

---

### .bss — глобальні неініціалізовані та ініціалізовані 0 дані

У програмі є глобальні змінні:

```cpp
SensorData sensorData;

bool useDHT = false;

unsigned long lastSensorTime = 0;
unsigned long lastHeapTime = 0;

bool lastButtonState = HIGH;
bool buttonState = HIGH;

unsigned long lastDebounceTime = 0;
```

Змінні, які не мають явного початкового значення або ініціалізовані нулем, зазвичай потрапляють до секції `.bss`.

Наприклад:

```cpp
SensorData sensorData;
```

є глобальним об'єктом.

Його поля:

```cpp
float temperature;        // 4 байти
float humidity;           // 4 байти
unsigned long timestamp;  // 4 байти
```

На ESP32 структура займає 12 байт і існує протягом усього часу роботи програми.

Змінні з ненульовим початковим значенням можуть розміщуватися в іншій секції RAM, наприклад `.data`, тому не всі глобальні змінні програми належать саме до `.bss`.

---

### Flash — пам'ять програми

Flash — енергонезалежна пам'ять ESP32, у якій зберігається скомпільований код програми.

Наприклад, машинний код функцій:

```cpp
generateRandomData()
validateSensorData()
readDHTData()
printSensorData()
handleButton()
setup()
loop()
```

зберігається у Flash і виконується мікроконтролером.

До Flash також потрапляють дані програми, які компілятор може зберігати як константні.

Після вимкнення живлення вміст Flash не втрачається, тому після наступного запуску ESP32 може знову виконати записану програму.

---

## 3. Підсумок на прикладі програми

| Область | Приклад з програми | Призначення |
|---|---|---|
| Stack  `temperature`, `humidity`, `sensorStatus`, `reading` | Локальні дані функцій |
| Heap | контролюється через `ESP.getFreeHeap()` | Динамічна пам'ять |
| .bss | `sensorData`, `lastSensorTime`, `lastHeapTime` | Глобальні нульово ініціалізовані дані |
| Flash | `setup()`, `loop()`, `readDHTData()` та інший код | Зберігання програми |

## Висновок

У програмі дані сенсора об'єднані в структуру `SensorData`, для локальних операцій використовуються змінні у стеку, а глобальні змінні існують протягом усього часу роботи програми.

Стан DHT22 зберігається у змінній `uint8_t sensorStatus`, де окремі біти використовуються як флаги стану температури та вологості.

Контроль `ESP.getFreeHeap()` протягом 5 хвилин показав стабільне значення 351012 байт, тому ознак витоку динамічної пам'яті не виявлено.

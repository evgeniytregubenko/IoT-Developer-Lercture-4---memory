# ESP32 Sensor Data, Heap and Bitwise Debug

Навчальний проєкт для ESP32, створений у PlatformIO та протестований у симуляторі Wokwi.

Проєкт демонструє роботу зі структурами даних, генерацією випадкових значень, неблокуючими таймерами на основі `millis()`, контролем вільної heap-пам'яті ESP32 та побітовими операціями.

Додатково до основного завдання реалізовано роботу з цифровим сенсором DHT22 та можливість перемикання джерела даних за допомогою кнопки.

---

## Основні задачі

У межах основного завдання реалізовано:

- структуру `SensorData` для зберігання температури, вологості та timestamp;
- генерацію випадкової температури в діапазоні від 15.0 до 30.0 °C;
- генерацію випадкової вологості в діапазоні від 30.0 до 65.0 %;
- формування timestamp на основі реального часу роботи ESP32;
- виведення даних у Serial Monitor кожні 20 секунд;
- неблокуючу періодичність виконання задач за допомогою `millis()`;
- контроль вільної heap-пам'яті ESP32 за допомогою `ESP.getFreeHeap()`;
- виведення обсягу вільної пам'яті кожні 60 секунд;
- перевірку стабільності використання пам'яті протягом 5 хвилин;
- аналіз переповнення типу `uint8_t`;
- опис розміщення змінних у Stack, Heap, `.bss` та Flash.

---

## Додатково виконано

Для розширення функціональності програми додатково реалізовано:

- підключення цифрового сенсора температури та вологості DHT22;
- два джерела даних:
  - `RANDOM` — генерація випадкових значень;
  - `DHT22` — отримання даних із сенсора;
- перемикання між `RANDOM` та `DHT22` за допомогою кнопки;
- використання внутрішнього `INPUT_PULLUP` для кнопки;
- програмний debounce кнопки без використання `delay()` у головному циклі;
- перевірку коректності температури та вологості, отриманих із DHT22;
- формування статусного байта `sensorStatus`;
- використання окремих бітів для контролю температури та вологості;
- блокування запису некоректних даних DHT22 у структуру `SensorData`;
- виведення поточного джерела даних та діагностичних повідомлень у Serial Monitor.

## Підключення

У програмі використовуються:

```cpp
#define DHT_PIN 4
#define DHT_TYPE DHT22
#define BUTTON_PIN 14
```

Схема підключення:

| Компонент | ESP32 |
|---|---|
| DHT22 VCC | 3V3 |
| DHT22 DATA | GPIO4 |
| DHT22 GND | GND |
| Button | GPIO14 |
| Button | GND |

Для кнопки використовується внутрішній підтягуючий резистор ESP32:

```cpp
pinMode(BUTTON_PIN, INPUT_PULLUP);
```

Тому логічний стан входу:

```text
Кнопка відпущена  -> HIGH
Кнопка натиснута -> LOW
```

## Структура даних сенсора

Для зберігання пов'язаних даних використовується структура:

```cpp
struct SensorData {
  float temperature;
  float humidity;
  unsigned long timestamp;
};
```

Створюється глобальний об'єкт:

```cpp
SensorData sensorData;
```

На ESP32 поля структури займають:

```text
temperature -> 4 байти
humidity    -> 4 байти
timestamp   -> 4 байти
---------------------
Всього      -> 12 байт
```

Таким чином температура, вологість та час отримання даних зберігаються як єдиний об'єкт.

---

## Режими роботи

Програма підтримує два джерела даних:

```text
RANDOM
DHT22
```

Після запуску активний режим:

```text
RANDOM
```

Це задається змінною:

```cpp
bool useDHT = false;
```

Натискання кнопки змінює її стан:

```cpp
useDHT = !useDHT;
```

Таким чином джерело даних циклічно перемикається:

```text
RANDOM -> DHT22 -> RANDOM -> DHT22 -> ...
```

При зміні режиму в Serial Monitor виводиться:

```text
Data source switched to DHT22
```

або:

```text
Data source switched to RANDOM
```

---

## Генерація випадкових даних

У режимі `RANDOM` температура та вологість генеруються функцією:

```cpp
void generateRandomData()
```

Температура:

```cpp
sensorData.temperature = random(150, 301) / 10.0;
```

Діапазон:

```text
15.0 ... 30.0 °C
```

Вологість:

```cpp
sensorData.humidity = random(300, 651) / 10.0;
```

Діапазон:

```text
30.0 ... 65.0 %
```

Функція `random()` не включає верхню межу, тому для отримання максимальних значень `300` та `650` використовуються верхні межі `301` та `651`.

Timestamp формується за допомогою:

```cpp
sensorData.timestamp = millis();
```

## Ініціалізація генератора випадкових чисел

Wokwi підтримує симуляцію генератора випадкових чисел ESP32.

Для отримання початкового значення `seed` використовується:

```cpp
randomSeed(esp_random());
```

Функція `esp_random()` повертає випадкове 32-бітне значення, яке використовується для ініціалізації генератора `random()`.

---

## Робота з DHT22

У режимі `DHT22` дані отримуються безпосередньо із сенсора.

Ініціалізація виконується у `setup()`:

```cpp
dht.begin();
```

Читання вологості:

```cpp
float humidity = dht.readHumidity();
```

Читання температури:

```cpp
float temperature = dht.readTemperature();
```

Після отримання значень виконується перевірка їх коректності.

---

## Bitwise-контроль даних DHT22

Для контролю коректності отриманих значень використовується 8-бітна змінна:

```cpp
uint8_t sensorStatus;
```

Кожний біт використовується як окремий прапорець:

```text
Bit 0 -> temperature OK
Bit 1 -> humidity OK
```

Початкове значення:

```cpp
uint8_t sensorStatus = 0b00000000;
```

Якщо температура коректна, встановлюється Bit 0:

```cpp
sensorStatus |= 0b00000001;
```

Якщо вологість коректна, встановлюється Bit 1:

```cpp
sensorStatus |= 0b00000010;
```

Можливі значення статусу:

| `sensorStatus` | Temperature | Humidity |
|---|---|---|
| `00000000` | ERROR | ERROR |
| `00000001` | OK | ERROR |
| `00000010` | ERROR | OK |
| `00000011` | OK | OK |

Для нормальної роботи обидва біти повинні бути встановлені:

```cpp
if ((sensorStatus & 0b00000011) != 0b00000011) {
  Serial.print("DHT22 read error | Status: 0b");
  Serial.println(sensorStatus, BIN);
  return false;
}
```

Таким чином одна змінна типу `uint8_t` використовується для зберігання декількох незалежних станів.

---

## Перевірка даних DHT22

Для визначення коректності значень використовується `isnan()`:

```cpp
if (!isnan(temperature)) {
  sensorStatus |= 0b00000001;
}
```

та:

```cpp
if (!isnan(humidity)) {
  sensorStatus |= 0b00000010;
}
```

`NaN` означає `Not a Number`.

Якщо DHT22 не зміг повернути коректне значення, воно не записується в `sensorData`.

Функція читання повертає:

```text
true  -> дані коректні
false -> помилка читання
```

---

## Періодичне виконання задач

У `loop()` не використовується блокуючий `delay()`.

Для організації періодичних задач використовується:

```cpp
millis()
```

Визначено два незалежні інтервали:

```cpp
const unsigned long SENSOR_INTERVAL = 20000;
const unsigned long HEAP_INTERVAL = 60000;
```

Тобто:

```text
Sensor Data -> кожні 20 секунд
Heap Check  -> кожні 60 секунд
```

Перевірка даних сенсора:

```cpp
if (millis() - lastSensorTime >= SENSOR_INTERVAL) {
  ...
}
```

Перевірка Heap:

```cpp
if (millis() - lastHeapTime >= HEAP_INTERVAL) {
  ...
}
```

Такий підхід дозволяє програмі продовжувати виконувати інші задачі між періодичними операціями.

---

## Обробка кнопки

Кнопка перевіряється при кожному виконанні `loop()`:

```cpp
handleButton();
```

Для усунення брязкоту контактів використовується програмний debounce:

```cpp
const unsigned long DEBOUNCE_DELAY = 50;
```

Після стабільного переходу кнопки у стан `LOW` виконується:

```cpp
useDHT = !useDHT;
```

Це дозволяє одним натисканням перемикати джерело даних.

---

## Контроль Heap

Для визначення обсягу вільної динамічної пам'яті ESP32 використовується:

```cpp
ESP.getFreeHeap();
```

Значення виводиться кожні 60 секунд:

```cpp
Serial.print("Free Heap: ");
Serial.print(ESP.getFreeHeap());
Serial.println(" bytes");
```

---

## Результат тестування Heap

Програма була протестована протягом 5 хвилин.

Отримані значення:

```text
60 s  -> 351012 bytes
120 s -> 351012 bytes
180 s -> 351012 bytes
240 s -> 351012 bytes
300 s -> 351012 bytes
```

Зміна обсягу вільної пам'яті:

```text
Δ Heap = 0 bytes
```

Вільна heap-пам'ять протягом тестування залишалася стабільною.

Отже, ознак витоку пам'яті (`memory leak`) під час тестування не виявлено.
